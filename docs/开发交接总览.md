# Synapse 开发交接总览（一期）

- 版本：v1.2（平台抓取实作 + 平台抓取单测补齐）
- 更新时间：2026-02-27
- 适用范围：本地单机应用（Electron + 本地 Server + Web UI）

## 1. App 概述（目标用户、核心价值）

### 1.1 目标用户
- 面向长期学习 AI、Agent、产品设计等知识的个人用户。
- 使用场景以本地资料沉淀、复盘、问答检索为主。

### 1.2 核心价值
- 把分散的学习资料沉淀为可检索、可复用的本地知识库。
- 自动生成精简总结与详细整理，降低复习成本。
- 问答过程可观测：实时看到引用文档、阶段过程、进度和最终输出。
- 为后续扩展公众号/小红书、音频/视频、向量检索预留架构。

## 2. 功能模块划分

### 2.1 资料导入模块
- 输入 URL 导入图文资料。
- 导入链路：安全校验 -> 内容抓取 -> Markdown 生成 -> 文件落盘 -> 入库 -> 异步任务。
- 每份资料一个独立目录。

### 2.2 资料管理模块
- 列表查询、按状态/关键词/分类筛选。
- 查看原文、精简总结、详细整理。
- 后续支持资料详情页内持续会话。

### 2.3 AI 异步加工模块
- 任务队列与重试。
- 生成 `brief_summary.md`、`detailed_notes.md`、`classification_suggestion.json`。

### 2.4 问答模块（全局 / 单资料）
- SSE 流式回答。
- 渐进式披露检索：`brief -> detailed -> original`。
- 运行取消与超时控制。

### 2.5 分类树模块
- 分类树 CRUD。
- 资料与分类绑定（手动 + AI 建议）。
- 问答支持按分类缩小范围。

### 2.6 设置与桌面模块
- 知识库根目录、LLM 配置。
- Electron 壳负责本地进程与系统能力（目录选择）。

## 3. 当前开发阶段

- 一期整体进度：约 `99%`。
- 已打通主链路：`导入 -> 异步生成 -> 流式问答 -> 四大模块渲染 -> 会话历史统一入口 -> 全局/单资料历史会话 -> 分类树管理 -> 设置页配置闭环 -> 引用定位交互 -> 分类过滤树选多选 -> 断线恢复提示`。
- 当前仍是“可运行原型 + 架构骨架”，未到生产可用状态。

## 4. 技术选型

### 4.1 仓库结构
- `apps/server`：Fastify + SQLite + 任务 Worker + SSE。
- `apps/web`：React + Vite + TypeScript。
- `apps/desktop`：Electron 主进程 + preload。
- `packages/shared`：共享类型（Req/VO/SSE/Event）。

### 4.2 通信架构
- UI -> Server：`HTTP REST + SSE`。
- Electron Main -> Renderer：`IPC`（仅桌面能力）。
- Server 内部：模块调用 + DB 任务轮询（不使用 RPC）。

### 4.3 数据存储
- SQLite：业务结构化数据。
- 本地目录：资料原文、图片、AI 产物、会话日志。

### 4.4 AI 策略
- `OpenAiCompatibleProvider` 抽象层。
- 支持配置 `baseUrl + apiKey + model`。
- 问答链路可降级 mock 并在阶段事件透出降级原因；AI 异步任务禁用静默 fallback，异常显式失败并记录。

## 6. 已实现功能（按代码事实）

### 6.1 后端
- SQLite 初始化、迁移执行与默认分类初始化。
- 首次迁移兜底：启动时先确保 `schema_migrations` 存在，避免新库首启报错。
- SQLite 驱动兼容：`better-sqlite3` 不可用时自动回退 `node:sqlite`（用于当前 Node 25 环境）。
- 导入状态语义收敛：
  - 重复导入时返回数据库真实 `status`，不再固定返回 `ready`。
  - 导入链路异常时回写 `status='failed'`、`ingest_stage='failed'`，避免卡在 `ingesting`。
  - AI 失败可重试场景回写阶段为 `queued`；超过重试上限后回写 `failed`。
  - 资料总状态按子任务阶段自动收敛：进行中为 `processing_ai`、全完成为 `ready`、终态失败为 `failed`。
  - 手动重试 `/api/jobs/:id/retry` 时同步将资料状态拉回 `processing_ai` 并设置对应阶段为 `queued`。
- 导入失败恢复与清理工具：
  - 新增 `/api/materials/recovery/import-failures`，支持按 `materialIds` 定向恢复。
  - 支持 `execute=false` 预演（dry-run）与 `execute=true` 执行模式。
  - 支持孤儿 staging 目录清理（可配置最小存活分钟数，默认 30 分钟）。
- LLM 可观测性增强：
  - AI 异步任务调用 LLM 时禁用 fallback，服务异常会显式抛错并进入任务失败重试链路。
  - 资料状态支持回写 `error_message`，列表/详情接口可直接查看失败原因。
  - 问答链路若降级到 mock，会在 `synthesize_answer` 阶段透出降级提示。
- 资料导入：
  - URL 安全校验（协议 + 内网拦截）。
  - 判重（`canonical_url + content_hash`）。
  - staging -> final 落盘。
  - 写入 `meta.json`、`source.html`、`source.md`。
  - 平台抓取器落地：`wechat/xiaohongshu` 适配器已支持自动抓取（复用通用抓取链路并保留平台 `sourceType`）。
  - 平台分发规则修正：显式 `sourceTypeHint=web_page` 时不再被平台域名强制接管。
- AI 任务：队列、重试退避、状态更新。
- 分类树：CRUD + 绑定（支持删除前子节点校验、移动防环校验）。
- 问答：SSE 流式、阶段追踪、引用输出、取消、超时。
- 会话线程列表：支持按范围 + 关键词检索，并回传资料标题用于快速定位。
- 设置：本地存储，API key 掩码返回。
- 检索主通路升级：
  - `searchByBrief` 从“逐条读取文件”切换为“优先读取 `material_search_fts` token 索引打分”。
  - `rerankByDetailed` 优先读取 `detailed_notes_tokens` 打分，仅对入选候选回读详细整理正文。
  - 保留历史数据文件回退兜底（索引缺失时自动读取文件计算）。
  - 分类绑定与 AI 分类任务完成后会触发索引刷新，降低索引滞后风险。
- 渐进式门控优化：
  - 原文读取引入门控配额（详细命中强时最多补 1 份，整体偏弱时最多补 2 份）。
  - 引入精简相关度下限，避免低相关候选触发无效原文读取。
  - 无可用详细整理时保留兜底原文读取，降低空上下文风险。
  - `retrieval.selected` 事件透出原文读取/跳过决策理由，增强可观测性。
- 单元测试补齐（第二批）：
  - 新增 `apps/server/tests/retrieval-service.test.ts`，覆盖 `rerankByDetailed` 的强命中配额、弱命中配额与兜底原文读取分支。
  - 新增 `apps/server/tests/chat-run-reducer.test.ts`，覆盖 `chatRunReducer` 的会话启动、阶段进度、引用去重与断线恢复状态映射。
  - 新增 `apps/server/tests/material-job-status.test.ts`，覆盖导入恢复状态语义、任务可重试失败回写、超过重试上限终态失败与 `finalizeMaterialStatus` 收敛逻辑。
- 服务集成测试补齐（第三批）：
  - 新增 `apps/server/tests/integration-flow.test.ts`，覆盖导入 -> AI 任务消费 -> 问答 SSE 事件流与 run/message 持久化主链路。
  - `pnpm --filter @synapse/server test` 已通过（13/13）。
- 平台抓取测试补齐（第四批）：
  - 新增 `apps/server/tests/platform-ingestors.test.ts`，覆盖公众号/小红书抓取器的显式类型导入、域名自动识别与分发优先级边界。
  - `pnpm --filter @synapse/server test` 已通过（17/17）。

## 8. Bug 与技术难点

### 8.1 已知风险
- 导入->任务->问答主链路已补齐一条集成回归，恢复工具与降级可观测性分支仍需继续补集成级覆盖。
- 复杂网页内容结构（表格、嵌套块、懒加载图片）保真不足。
- LLM 降级可观测性已增强，但仍缺少针对降级场景的自动化回归测试。
- Node 25 依赖兼容风险：当前使用 `node:sqlite` 回退可运行，但其在该版本仍有 Experimental 警告，建议后续收敛到稳定驱动策略。

### 8.2 技术难点
- 渐进式检索的门控与准确率平衡。
- 文件系统与数据库双写一致性。
- SSE 长连接在取消/超时/异常下的状态一致性。

## 9. 性能 / 安全 / 约束要求

### 9.1 性能
- 优先读取 summary 层，降低长文全量读取。
- AI 任务异步化，支持失败重试。
- 检索已完成 token 索引主通路，后续向量/混合检索演进。

### 9.2 安全
- URL 校验与私网拦截。
- 前端渲染需 sanitize（当前仍需加强）。
- API key 仅掩码回传。
- 提示词注入防护：只展示阶段摘要，不泄露模型隐式推理。

### 9.3 强约束
- 前后端隔离，先定义共享协议再联调。
- LLM 接口必须保持可替换。
- 每份资料与衍生文件必须同目录。
- 检索坚持渐进式披露。
- 输出与协作统一中文。
